# Phase 2.1 contract review

Scope: the four offline Sales Journey modules and the three Phase 2 test files.
The Graph/API/Phase 1.1 files were not modified.

| Contract area | Result | Evidence / boundary |
|---|---|---|
| State transitions | PASS | Explicit `JourneyStage` state machine; discovery, qualification, recommendation, comparison, objection, closing, follow-up, after-sales, handoff, paused and unknown paths covered. |
| Invalid transitions | PASS | Unknown stage input is rejected; invalid Pydantic state is discarded by the engine. |
| Tenant/conversation isolation | PASS | State scope checks tenant and conversation; mismatched state falls back to `UNKNOWN`. |
| Customer isolation | PASS | Caller-provided customer identity must exactly match state/memory; missing customer identity no longer acts as a wildcard. |
| Stale/corrupt state | PASS | Strict models reject malformed/extra data; state freshness is capped at 30 minutes and future/stale state is ignored. |
| Serialization version | PASS | Versioned `sales_journey_state` envelope; wrong schema/version/corrupt payload returns `None`. |
| Missing slots | PASS | Phase 1 `discover_needs` remains the source of truth and supplies at most one `next_best_question`; prior slots are reused only within scope and freshness. |
| Topic/product switching | PASS | Explicit reset cues create a new opaque goal and clear old slots/constraints while preserving scope. |
| Capability disabled | PASS | Existing `resolve_capability_request` is used fail-closed; no disabled tool/workflow is requested. |
| Missing dependencies | PASS | Dependency-unavailable catalog plan is denied, records missing dependencies/evidence requirements and requests handoff. |
| Evidence requirements | PASS | `ToolPlan.evidence_required` records current catalog, knowledge, comparison, workflow or transaction evidence; the engine does not invent facts. |
| Human handoff | PASS | Explicit human/sensitive/unsupported after-sales/capability boundaries route to handoff with a reason. |
| No forced closing | PASS | Information/price-first turns remain discovery/read-only; weak interest does not become closing. |
| No transaction without confirmation | PASS | Closing actions are offers only; `transaction_created=False`, no side effects, and no workflow execution. |
| No extra LLM calls | PASS | Engine and adapters are deterministic; every decision reports `llm_calls=0`, `network_calls=0`, empty side effects. |

## Hardening changes

1. `SalesJourneyState.is_fresh()` and `JOURNEY_STATE_TTL` establish the same
   short-lived boundary as the existing conversation-memory TTL.
2. `deserialize_state()` now rejects stale/future state in addition to corrupt,
   version-mismatched and cross-scope state.
3. `SalesJourneyEngine._safe_state()` and `_scope_matches_memory()` fail closed
   for stale or customer-unbound input when a caller customer is known.
4. `capability_config is None` is distinguished from an explicit empty mapping.
5. Offline tests were added for the above plus invalid transitions, pause
   stickiness, missing dependencies and the one-question contract.

## Residual integration conditions

- `InMemoryJourneyStateAdapter` is test-only and must not be used as production
  persistence.
- A future Graph change must load/save the versioned state through an approved
  existing durability boundary, preserving the 30-minute/scope checks.
- `ToolPlan` is a planning contract, not permission to execute. The existing
  Graph authorization and Answer Guard remain authoritative.
