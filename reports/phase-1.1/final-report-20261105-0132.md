## Architecture and behavior

**Before:** Phase 1 already provided 14 industry playbooks, industry resolution, Needs Discovery, and the existing LangGraph. The RFM and recommendation services also already existed.

**After:** tenant workspace config resolves business model, one-or-more industry IDs, recommendation reference profile, and explicit capability grants. A deterministic resolver limits available tools/workflows. The existing Sales Brain/industry playbooks and LangGraph then route permitted work to current catalog, knowledge, CRM, recommendation, and workflow paths. Existing evidence checks and natural-language response continue downstream.

Changing business model does not itself erase configuration/data or revoke explicitly enabled capabilities. Disabling a capability blocks new protected work; safe historical reads/edits are retained only where supported by existing workflow policy. CORE_CRM remains available.

## RFM and recommendation audit

- **RFM scoring:** fm_percentile_v1; Recency is days since the latest qualifying completed order, Frequency counts qualifying completed orders once per order, and Monetary uses net order amount. The profile also includes item counts/distinct products/AOV, but these are not a separate propensity prediction.
- **Segmentation:** existing shop-scoped MiniBatchKMeans uses log-transformed R/F/M, StandardScaler, a reproducible seed, and a minimum of 20 consented buyers. This threshold is a readiness rule, not a statistical quality guarantee. Insufficient/degenerate clusters use the RFM rules fallback.
- **Consent:** the shop model training path selects eligible consenting customers; serving personalization checks consent and customer opt-out. Withdrawal invalidation is existing privacy behavior and is not newly trained or tested against real data in this phase.
- **Purchase propensity:** no separate trained purchase-probability model with documented target labels, fit artifact, inference contract, and evaluation evidence was found. The API reports it unavailable; no probability is synthesized from RFM.
- **Recommendation:** existing item-affinity/RFM and optional LightFM candidate ranking remain recommendation ranking components. LightFM presence does not mean a trained model is currently active or a purchase probability. Existing serving gate requires enabled state and a passed quality gate.
- **Reference industry:** stored as an RFM segment prior/profile choice, not as a claim of a separately trained vertical model. Generic fallback remains for unsupported profiles.
