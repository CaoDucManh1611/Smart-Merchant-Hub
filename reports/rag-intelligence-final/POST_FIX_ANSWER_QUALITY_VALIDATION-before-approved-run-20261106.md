## Five offline fixes verified

1. Explicit product comparison now reaches the deterministic catalog comparison path instead of being stopped by a generic discovery prompt.
2. A short same-conversation follow-up can resolve the prior explicit product mention when persisted reply memory is empty; lookup remains bounded to the conversation.
3. An explicitly entered unknown SKU no longer gets fuzzy-matched to a similar SKU.
4. Same-name product variants include available size/color details in the clarification without exposing internal SKU codes.
5. A question combining price and a return window is no longer reduced to a price-only shortcut.

All five focused regression cases pass. This verifies deterministic routing/behavior offline; it does not verify model-generated answer quality after the fixes.

- Provider and infrastructure failures stay in reliability denominators but are excluded from answer grading. The grader marks their objective claims NOT_MEASURED; it does not count them as hallucinations.
- An extra combined tenant/capability/tool test command exited 1: the two tenant-isolation/capability files passed 35 tests, but 10 ChatbotAgentToolTests failed during setup because --noconftest omits the test-only metadata bootstrap in tests/conftest.py (it normally creates TenantBase tables alongside LegacyBase). The failure occurred before test behavior; the two passing files were rerun alone. See test-postfix-tenant-auth-20261106.log and execution-post-fix-validation-20261106.md.
- Automated checks cover selected objective claims only. Naturalness, complete grounding, whether sources support every sentence, and overall usefulness need a human reviewer. No machine-generated label was promoted to a human label.
- output_schema_validity is NOT_CAPTURED because the stored run result retains final text, not the raw structured-output object. For selected tools, only selection is present; execution-level database writes are not represented.
- The retrieval benchmark runs actual retrieve() BM25 against synthetic in-memory SQLite rows. It does not exercise vector retrieval, provider embedding, graph answer generation or production PostgreSQL.
- No source code was changed during this validation pass. Existing dirty work was preserved. No provider, customer channel, production database, migration, reindex, transaction, commit, push or deploy was used.
- CONSENT_RACE_P2=OPEN; SALES_JOURNEY_ENGINE_ENABLED=False remains the default.
