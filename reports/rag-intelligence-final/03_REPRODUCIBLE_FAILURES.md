# Reproducible failure and diagnosis\n\n## Exact SKU plus a requested variant\n\n**Input:** `What is SKU AST-LAMP-MINI-01 and is it the full lamp?`\n**Expected evidence:** `aster:lamp-mini` and `aster:lamp-full`, exact item first.\n**Baseline actual:** only `aster:lamp-mini`; evidence recall 0.5. Same failure occurred for Birch and Cedar fixtures.\n\n**Root cause:** retrieval inferred a strict SKU filter from the exact identifier. That was correct for identifying the requested item, but the same filter excluded the counterpart needed to answer the explicit variant question. The generation layer therefore could not compare the products from its evidence.\n\nThe regression was first reproduced with the new synthetic retrieval test before the retrieval change; it failed with the comparison evidence missing. The 51-case baseline JSON independently records the same three misses.\n\n## Independent holdout\n\nAdded a separate Vietnamese query with an unseen SKU pattern and different product category:\n\n`Mã AST-MIRROR-M10-L có phải gương bên phải không?`\n\nExpected and tested order: left mirror exact SKU first, then the right-mirror evidence. The test also uses a synthetic tenant and confirms the requested right-side variant is available to retrieval. This one-case regression is not pooled into the 51-case benchmark score.\n\n## Guarded negatives\n\n- Exact SKU question without a counterpart variant still returns only the exact item.\n- A caller-supplied `hard_filters.sku` remains strict; companion expansion is skipped.\n- Unknown SKU remains empty and cannot broaden into a plausible item.\n- A foreign tenant’s matching variant is never returned.\n\nTest evidence: `backend/tests/test_rag_intelligence_regressions.py`; focused tests and full-suite results are recorded in `06_SECURITY_AND_REGRESSION.md`.\n
