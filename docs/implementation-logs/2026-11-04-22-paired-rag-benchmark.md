# Paired RAG benchmark contract

Date: 2026-11-04. This is an **offline comparison tool**, not a claim that the chatbot is more accurate in production. No customer message or model call was made for this artifact.

`backend/scripts/compare_rag_runs.py` accepts `--baseline`, `--candidate`, `--labels`, `--output` and `--min-cases-per-shop`. Both run files are JSON objects with a nonempty `cases` array. Each case needs `case_id`, `business_id`, `snapshot_id`, the actual 64-character `snapshot_sha256`, `question`, its SHA-256 `question_hash`, `model`, and the same `sampling_config`; optional `latency_ms`, `tokens`, `llm_calls`, `cost_usd`, `fallback_used`, and `ranked_source_ids`. The label CSV needs `case_id`, `business_id`, `reviewed_by`, and the six reviewed boolean columns `baseline_correct`, `candidate_correct`, `baseline_hard_error`, `candidate_hard_error`, `baseline_helpful`, `candidate_helpful`. Optional `gold_source_ids` is a JSON array for Recall@5 and NDCG@5. Source IDs must refer to the frozen snapshot; the comparer does not create or approve gold labels. `reviewed_by` is only a declared identifier, not an authenticated signature.

The script refuses missing/duplicate IDs, reviewer, label booleans, model, question hash, tenant or snapshot mismatch. The output records SHA-256 of each input, per-case correctness/hard errors, per-shop and overall counts, p50/p95 where all latencies are known, actual token/call/cost totals only where every row provides them, and retrieval metrics only for cases with both reviewed source gold and ranked IDs. Unknown is `null`, never zero. The hard-error gate requires zero candidate hard errors and no reduction in helpful answers; shops below the predeclared sample floor are `INSUFFICIENT`. Optional `--max-p95-ms` and `--max-cost-usd-per-case` must be fixed before the run; unknown measured values block these gates, and excessive values fail. Overall cannot pass when any shop is insufficient or fails. `PASS_OFFLINE` is not a live deployment gate.

Focused test command from repo root: `python -m pytest -q backend/tests/test_compare_rag_runs.py --tb=short` → **6 passed** on the current workspace. The tests cover paired counts, per-shop sample floor, snapshot mismatch, missing usage, hard error, absent reviewer, retrieval gold ranking, and predeclared latency/cost limits. They do **not** measure actual answer quality.

Next evidence required: frozen catalog/doc snapshot for several industries, independently reviewed questions and source labels, separate baseline and candidate answers with the same question/model, provider attempts and webhook-to-delivery timestamps, then staging replay of 429/timeout/media adapters. Keep BM25/PPR-off baseline and new vision/adaptive features behind flags until per-shop hard errors, helpfulness, p95 and cost gates are met.

`backend/scripts/prepare_rag_human_review.py` now creates the review sheet only after baseline and candidate match on tenant, snapshot hash, question hash, model and sampling configuration. All reviewer and decision cells are blank, existing files are never overwritten, and mismatched runs fail closed. A human reviewer fills the six boolean decisions, reviewer identity, time, gold source IDs and notes; only then may `compare_rag_runs.py` consume the sheet. AI suggestions may be attached as notes but must not populate `reviewed_by` or convert pending rows to approved labels.
